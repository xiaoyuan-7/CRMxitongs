## 修复备份 cron 投递失败（154 次连续报错）

### 根因
`~/.openclaw/cron/jobs.json` 里 job `9084f652` 的 `delivery` 只有 `{"mode":"announce"}`，
**没有 channel 和 target**。备份脚本本身每天都成功（3 个分支全部推送成功），
挂的只是"把结果告诉你"这一步。连续 154 次报
`Delivering to QQ Bot requires target QQ Bot target format: qqbot:c2c:openid`

### 修复
```json
"delivery": {
  "mode": "announce",
  "channel": "qqbot",
  "target": "qqbot:c2c:9DC0F8EF889BF0527D6DAA6C616FE98F"
}
```
- openid 来源：查 `~/.openclaw/agents/main/sessions/*.jsonl` 里的 `[QQBot] to=` 标记
- 用一次性 cron job 做真实投递测试 → 已发出一条测试消息验证通道可用
- 测试 job 已删除；`consecutiveErrors` / `lastError` 已重置
- 改 jobs.json 前留了带时间戳的 .bak

### 排查命令备忘

### ⚠️ 关键修正：delivery 字段名是 `to`，不是 `target`
第一次修复我写成了 `delivery.target`，**完全无效**。
源码 `dist/server.impl-BbJvXoPb.js` 的 `resolveCronDeliveryPlan()`：
```js
const deliveryTo = normalizeOptionalString(delivery?.to);   // ← to
const deliveryChannel = normalizeChannel(delivery?.channel);  // ← channel
```
正确写法：
```json
"delivery": { "mode": "announce", "channel": "qqbot", "to": "qqbot:c2c:<openid>" }
```

### 端到端验证方法（可复用）
把 job 的 `schedule.expr` 临时改成 `"* * * * *"` + `state.nextRunAtMs` 设为 90 秒后，
等它自然触发 → 看 `state.lastDeliveryStatus` 是否为 `delivered` → 再改回原 expr。
（改 `jobs.json` 磁盘文件**不需要重启 gateway**：每次执行到期任务前
`ensureLoaded(state, {forceReload:true})` 会重读磁盘。）

实测结果：`lastStatus: ok` + `lastDeliveryStatus: delivered`，
备份三部分全推送成功（workspace-backup / workspace-crm-backup / industry-research-backup）。
