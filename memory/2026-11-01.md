### 移动端问题 1：页面只剩两个标题（根因是路径，不是样式）
现象：手机上打开只看到「对公行业研究」+「首页」两个标题。
**根因**：页面所有资源是相对引用（`src="app.js"`、`href="dashboard.html"`），而从 `/research/` 提供 `index.html`，浏览器把 `app.js` 解析成 `/research/app.js` → 404，`data.js` 同样 404 → JS 全挂 → 只剩静态 HTML 的两个标题。
**修法**：`/research/` → **301 跳转** `/research/web/index.html`，让 URL 与真实目录一致，相对引用自然解析正确。
（曾误判为「已部署好」，实际是路径错。教训：先看浏览器 Network 里的 404，不要凭资源文件存在就认为加载成功。）

## workbench 移动端加载优化（续，01:00 完成）

### 根因链（三层，逐层剥）
1. **JS 字面量解析阻塞**：`window.X = {...}` 形式 69MB，浏览器当 JS 源码解析（scriptEval 1126ms vs JSON.parse 241ms，差 4.7 倍）
   → 改 `fetch + JSON.parse`（workbench/data-loader.js）
2. **实时 gzip 抢 CPU**：服务器仅 2 核，11 个并发请求各自实时压缩，160KB 的 aggregates.json 要 10.6s（13KB/s）
   → `scripts/precompress.sh` 预生成 `.gzcache/`，static-server 优先读预生成文件（零 CPU）
3. **br 优先级坑**：Chrome 发 `Accept-Encoding: gzip, deflate, br, zstd`，旧逻辑优先响应 br → 走实时 brotli 更慢
   → 改成"缓存命中就优先 gzip"（HTTP 允许服务端在多个可接受编码中任选）

### 实测对比
| 阶段 | 之前 | 之后 |
|---|---|---|
| 本机 11 文件并发 | ~40s | 125ms |
| 手机端整体加载 | 40s 卡在 82% | 5s（本机）/ 15s（公网） |
| 单文件 companies.json | 1.3s | 0.09s |

### grid 溢出陷阱（移动端筛选区看着是空的）
`filter-panel` 有 `width:fit-content` + sticky，窄屏撑到 1124px 溢出屏幕外。
**修法关键是 grid item 的 `min-width:auto`** —— `.companies-layout` 的 `1fr` 列会被内部超宽内容撑开，
必须写 `grid-template-columns: minmax(0,1fr)` + 子项 `min-width:0`，光加 `width:100%!important` 没用。

### 其他

- CSS 改动要同步刷 `.gzcache/`（否则浏览器拿到旧 gzip）：`gzip -6 -c <file> > .gzcache/<path>.gz.tmp && mv`
- CSS 引用加版本号防缓存：`styles.css?v=20261101-1`

## 19:46 手机端「输入用户名密码没反应」→ 改表单登录（已修）

### 现象
用户在手机端打不开 workbench，浏览器弹 Basic Auth 框，输入用户名密码**没反应**（一直转/反复弹）。

### 排查结论
- 服务器侧全正常：隧道（sanyo-concluded-opponent-heating.trycloudflare.com）、auth-proxy 3100、
  static 8000、backend 3001 均在线，公网 curl 200。
- 移动端模拟（CDP iPhone 15, 390×844）workbench 布局本身没问题（docH 4102、无 console 错误）。
- **根因是认证方式**：Basic Auth 弹窗在手机浏览器/QQ 内置浏览器里经常不响应，
  密码又轮换过一次（旧密码 `LZdSfrGpMmzLm1` → 新密码 `oSty45kTwKhRgYVZYMnr`），
  输错时浏览器只是重复弹框，用户感知就是「没反应」。
- 次要因素：隧道到国内手机端只有 ~80KB/s（CF 边缘是 LAX），大 JSON 首屏要 30~50 秒。

### 改动
1. `scripts/auth-proxy.js`：**新增表单登录 + Cookie 会话**
   - `GET /__login` 返回移动端自适应登录页（16px 输入框、48px 大按钮，避免 iOS 自动缩放）
   - `POST /__login` 校验后下发 `crm_auth` Cookie（HMAC(secret,user)，30 天，HttpOnly、SameSite=Lax）
   - 未授权时：浏览器（Accept 含 text/html）→ **302 跳 /__login，不再弹 Basic Auth**；
     非浏览器（curl 等）→ 仍返回 401 + `WWW-Authenticate`，保持脚本可用
   - 新增 `GET /__logout`；代理新增每请求访问日志（方法/URL/状态/IP），便于看手机请求是否到达
2. `scripts/static-server.js`：支持**预压缩 brotli**（`scripts/precompress-br.sh` → `.gzcache/**/*.br`）
   - 但**对同时支持 br+gzip 的浏览器优先发 gzip**：实测 Cloudflare 边缘会把上游 br 解开再压成 gzip，
     公网拿到的仍是 2.19MB（=gz 大小），发 br 只会让边缘多一次解压+重压
3. `scripts/crm-url.sh`：多打印「工作台」「登录页」两条地址
