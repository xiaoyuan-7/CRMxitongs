# 2026-11-02

## 入口拆分：CRM 回到直连 IP，工作台独立成平台

**用户诉求**：workbench 链接登录后跳到 CRM；要求 CRM 回到 `http://47.96.177.153:3001`，
另外单独给工作台一个平台地址。

### 端口事实（用 check-host 外部节点实测，别只在服务器上 curl）
- 安全组放行：22、80、443、3001（外部返回 refused = 到了主机但没监听 → 已放行）
- 安全组拦截：3100、8000 等其他端口（外部 timeout）
- 关键：`127.0.0.1:3001` 自测能通不代表公网通，要用外部节点验

### 新架构
| 入口 | 地址 | 链路 |
|---|---|---|
| CRM | `http://47.96.177.153:3001/` | auth-proxy(0.0.0.0:3001, 仅CRM) → backend(127.0.0.1:3011) |
| 工作台 | `http://47.96.177.153/` → `/workbench/index.html` | auth-proxy(0.0.0.0:80, PROXY_MODE=static) → static(8000) |
| 隧道 | `https://sanyo-...trycloudflare.com/` | cloudflared → auth-proxy(127.0.0.1:3100) → backend + `/research/*`、`/workbench/*` |

- backend 从 3001 挪到 **3011**（只听 127.0.0.1），把 3001 让给公网代理
- 绑 80 端口需要 root：`sudo setcap 'cap_net_bind_service=+ep' /usr/bin/node`（admin 用户非 root）
- 幂等重建脚本：`scripts/setup-endpoints.sh`（pm2 save 已做）

### auth-proxy.js 增强
- `LISTEN_HOST`（默认 127.0.0.1）、`PROXY_MODE`（crm|static）、`STATIC_INDEX`
- **return_to**：未登录跳转 `/__login?rt=<原路径>`，登录成功回到原路径
  → 修掉了「打开工作台 → 登录 → 落到 CRM」的老毛病
- 密码改走环境变量 `PROXY_PASS`，不再出现在 ps 命令行
- static 模式：`/` 302 到 `/workbench/index.html`（URL 必须与真实目录一致，
  否则相对引用 styles.css / data/*.json 全 404）
- crm 模式下新增 `/workbench/*` 直通静态站（隧道短路径）

### 实测性能（13.6MB companies.json）
- 直连公网 IP：**0.19s / 70MB/s**
- Cloudflare 隧道：~300KB/s（CF 边缘落 LAX，绕太平洋）
→ 工作台首屏务必走直连 IP，隧道只当备用
